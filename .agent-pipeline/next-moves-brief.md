Two parallel, barely-connected apps. ## 5. Honest gap between "v1.4 app" and a paid product
The backend is genuinely good; **the product is not there.** Blunt version: (a) the two capabilities the entire consumer pivot is sold on — recurring detection and savings summary — **exist only as JSON endpoints that no user can see**; (b) they are not even to spec (`price_trend`/`currency` missing, `period` ignored); (c) the savings number is arithmetically unsound as a sales claim: `potential_saving = sum(max(0, total_c − avg_c))` (`app/savings.py:61-64`) subtracts an average **computed from the very same window that includes the overspend**, so it is close to a self-cancelling ~0 and will read as $0 to most households; (d) `currency` is hardcoded `"USD"` (`app/savings.py:93`) while the plan targets HU consumers; (e) **no payment path exists** (0 Stripe files) and **no validation ever ran** (V0.1/V0.2 never executed), so there is no evidence anyone wants this. A user would pay for a *notification* — "your groceries went up 14%, cancel this" — and that loop is exactly what is missing. The honest sequence is: fix (c), surface on the dashboard, add one alert, *then* ask for money.
